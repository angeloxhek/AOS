# AOS - Advanced Operating System

# RU (Русский)

Актуально для версии коммита 108.

## Что это?

**AOS (Advanced Operating System)** — это высокопроизводительная многозадачная **микроядерная** операционная система **с концепцией минимального доверия** и поддержкой различных архитектур процессора при помощи HAL, основанная на архитектуре **x86_64**.

## Философия

В основе AOS лежит **концепция минимального доверия и минимального вмешательства ядра в работу приложений**, при этом критические компоненты оптимизированы для работы в защищенном режиме. Также AOS **отличается легким IPC**, не компрометирующий безопасность.

В AOS **драйвером является процесс**. ОС разделяет драйвера на 2 вида:
- **Демон** - любой процесс, зарегистрированный как драйвер для работы с IPC в целях привязки постоянного имени к текущему процессу, но не требующий специальных прав.
- **Аппаратный драйвер** - приложение, имеющее особую точку входа и имеющую специальную секцию с информацией о драйвере.

Также одна из идей AOS - возможность портирования программ линукса (работа других ОС не гарантируется, даже если все необходимые функции предоставлены). Подробнее здесь -> [AOSLIB-linux](https://github.com/angeloxhek/AOSLIB-linux) <-

**AOS имеет независимое API (AOSLIB)**, обеспечивающее весь функционал системы, в отличие от портов. В портах функционал выходит чуть позже. Подробнее здесь -> [AOSLIB](https://github.com/angeloxhek/AOSLIB) <-

**AOS использует библиотеку AGFX в качестве инструмента для отрисовки интерфейса**. Данная библиотека встроена в AOSLIB. Подробнее здесь -> [AGFX](https://github.com/angeloxhek/AGFX) <-

AOS имеет специальный драйвер для запуска других различных драйверов (в том числе и от сообщества) - initdriver. Однако имеются другие обязательные драйвера, которые загружаются напрямую загрузчиком. Подробнее здесь -> [Содержимое и структура INITRD.TAR](docs/ru/files.md#содержимое-и-структура-initrd-tar) <-

AOS в качестве исполняемых файлов поддерживает любые файлы формата **ELF64** (ELF32 на данный момент не поддерживается, расширение не обязательно, однако драйвера, находящиеся внутри initrd \[см. [Содержимое и структура INITRD.TAR](docs/ru/files.md#содержимое-и-структура-initrd-tar)\] имеют особенности в именовании).

**Основная идея AOS - минимальное доверие**. Некоторые поля из сообщения IPC являются достоверными, так как заполняются ядром (см. IPC). Основным доверителем прав является authdriver. Главная особенность системы прав - невозможность повышения прав выше контекста, через который был создан запрос (см. authdriver). Исключение из этого правила - повышение через драйвер доверия и защищенного пространства (в разработке).

vfsdriver имеет виртуальную файловую систему ipcfs, что **упрощает создание удаленных файловых систем** через IPC (см. ipсfs).

## Установка

Релизы выпускаются в виде iso и vhd файлов. Оба образа содержат все необходимые файлы для запуска. vhd файл готов к запуску на QEMU напрямую.

**На данный момент стабильно поддерживается загрузка через MBR (BIOS). Поддержка UEFI находится в активной разработке и будет доступна в ближайших коммитах.**

Для информации о том, как скомпилировать ОС, лежит в другом файле. Подробнее здесь -> [Компиляция](docs/ru/build.md) <-

Для установки на флешку (или для создания vhd) необходимо выполнить следующие действия:

### Windows

Для UEFI пропустите шаги 3, 4, 5. Для MBR пропустите шаг 7.
1. Необходимо скачать программу BOOTICE и разархивируйте образ в любую удобную папку.
2. Форматируйте раздел на FAT32 с помощью стандартных утилит Windows (не сторонние, требуется именно от Windows).
3. Запутите BOOTICE, выбирите желаемый диск, нажмите Process PBR, выберите желаемый раздел, нажмите Restore PBR.
4. Выберите файл pbr.bin (**НЕ PBRLDR.BIN**). Проверьте значение sectors - оно должно быть 1. А также проверьте галочку "**Keep BPB untouched**", она обязана быть установлена.
5. Нажмите Restore, Close и Exit
6. Скопируйте все разархивированные файлы в корень раздела. Проверьте наличие файла `F:\AOSLDR.BIN`, где F: - буква раздела, на который устанавливается ОС.
7. Для UEFI: проверьте наличие файла `F:\EFI\BOOT\BOOTX64.EFI`, где F: - буква раздела, на который устанавливается ОС.

### Linux

Для работы с разделами вам понадобятся права суперпользователя. Для UEFI пропустите шаг 4.

1. Скачайте релизный архив и разархивируйте его содержимое в любую удобную папку.
2. Подключите флешку и выполните команду в терминале, чтобы узнать её имя (например, `/dev/sdb`):
   ```bash
   lsblk
   ```
3. Создайте на флешке чистую файловую систему FAT32. Замените `/dev/sdX1` на имя вашего раздела:
   ```bash
   sudo mkfs.vfat -F 32 /dev/sdX1
   ```
4. Для записи загрузочного сектора раздела используйте утилиту `dd`.
   ```bash
   sudo dd if=path/to/pbr.bin of=/dev/sdX1 bs=1 count=3 conv=notrunc
   sudo dd if=path/to/pbr.bin of=/dev/sdX1 bs=1 skip=90 seek=90 conv=notrunc
   ```
   *Здесь `path/to/pbr.bin` — это путь к файлу `pbr.bin` (НЕ `pbrldr.bin`) из разархивированного релиза.*
5. Смонтируйте раздел и перенесите все файлы из архива в корень флешки:
   ```bash
   sudo mount /dev/sdX1 /mnt
   sudo cp -r path/to/extracted/files/* /mnt/
   sync
   ```
6. Убедитесь, что файл загрузчика находится строго по пути `/mnt/AOSLDR.BIN` (а для UEFI дополнительно проверьте наличие `/mnt/EFI/BOOT/BOOTX64.EFI`), после чего отмонтируйте накопитель:
   ```bash
   ls /mnt/AOSLDR.BIN
   sudo umount /mnt
   ```

## Запуск

Запуск на реальном ПК происходит так же, как и в других ОС (через Boot Menu материнской платы).

### QEMU

Для запуска необходимо скачать/собрать vhd файл с образом.

`<arch>` - архитектура процессора, должен совпадать с архитектурой в образе

**IDE / ATA:**

Для нормального запуска:
```batch
# Windows
"%PROGRAMFILES%\qemu\qemu-system-<arch>.exe" -hda disk.vhd

# Linux
qemu-system-<arch> -hda disk.vhd
```

Для запуска с записью логов:
```batch
# Windows
"%PROGRAMFILES%\qemu\qemu-system-<arch>.exe" -gdb tcp:0.0.0.0:1234 -hda disk.vhd -d guest_errors,unimp,cpu_reset -D qemu.log -no-reboot -no-shutdown -serial file:syslog.log

# Linux
qemu-system-<arch> -gdb tcp:0.0.0.0:1234 -hda disk.vhd -d guest_errors,unimp,cpu_reset -D qemu.log -no-reboot -no-shutdown -serial file:syslog.log
```

**AHCI/SATA:**

Для нормального запуска:
```batch
# Windows
"%PROGRAMFILES%\qemu\qemu-system-<arch>.exe" -device ahci,id=ahci -drive id=disk,file=disk.vhd,if=none,format=vpc -device ide-hd,drive=disk,bus=ahci.0

# Linux
qemu-system-<arch> -device ahci,id=ahci -drive id=disk,file=disk.vhd,if=none,format=vpc -device ide-hd,drive=disk,bus=ahci.0
```

Для запуска с записью логов:
```batch
# Windows
"%PROGRAMFILES%\qemu\qemu-system-<arch>.exe" -gdb tcp:0.0.0.0:1234 -device ahci,id=ahci -drive id=disk,file=disk.vhd,if=none,format=vpc -device ide-hd,drive=disk,bus=ahci.0 -d guest_errors,unimp,cpu_reset -D qemu.log -no-reboot -no-shutdown -serial file:syslog.log

# Linux
qemu-system-<arch> -gdb tcp:0.0.0.0:1234 -device ahci,id=ahci -drive id=disk,file=disk.vhd,if=none,format=vpc -device ide-hd,drive=disk,bus=ahci.0 -d guest_errors,unimp,cpu_reset -D qemu.log -no-reboot -no-shutdown -serial file:syslog.log
```

## Разработка и Вклад в проект

Мы приветствуем создание сторонних драйверов и системных утилит на базе `AOSLIB` / `AGFX`. 

* **Оформление драйверов:** Помните, что аппаратные драйверы должны компилироваться в формат **ELF64** (или любой другой поддерживаемый системой напрямую) и содержать метаданные в специализированной секции заголовка.
* **Пулл-реквесты (PR):** Перед отправкой изменений убедитесь, что код соответствует общему стилю проекта, а сборки `make DEBUG=1` и `make` проходит без ошибок.
