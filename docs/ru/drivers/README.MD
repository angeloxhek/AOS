# Драйверы в AOS

Актуально для версии коммита 108.

В микроядерной архитектуре AOS **драйвер — это обычный процесс пользовательского пространства (Ring 3)**. Ядро не содержит в себе логики работы с файловыми системами, видеокартами или сетью. Вместо этого ядро предоставляет механику привилегий, маппинга памяти и [межпроцессного взаимодействия](../kernel/ipc.md), с помощью которых процессы-драйверы управляют оборудованием или предоставляют системные сервисы.

Операционная система строго разделяет драйверы на две категории: **Аппаратные драйверы** и **Демоны (Программные драйверы)**.

Для практического руководства по написанию кода см. -> [Стандарт и стиль написания аппаратных драйверов](style_guide.md) <-

## 1. Аппаратные драйверы

Аппаратные драйверы предназначены для непосредственного управления "железом". Им требуются особые привилегии, которые обычный процесс получить не может.

### Механизм регистрации
Аппаратный драйвер не регистрирует себя сам через системные вызовы. Вместо этого он декларирует свои требования на этапе компиляции с помощью специальной структуры метаданных, которая помещается в секцию `.driver_info` исполняемого файла ELF64 (через макрос `AOS_DECLARE_DRIVER`).

Когда ядро (или системный загрузчик) загружает такой ELF-файл в память, оно:
1. Находит секцию `.driver_info`.
2. Проверяет магическую сигнатуру.
3. Автоматически регистрирует процесс в глобальном реестре драйверов ядра с запрошенными правами.

### Привилегии аппаратных драйверов
Ядро AOS реализует концепцию минимального доверия. Драйвер получает только те права, которые он явно запросил в своих метаданных:

* **`DRV_PERM_IO_PORTS`** — Доступ к портам ввода-вывода (инструкции `in` / `out`). Ядро настраивает *I/O Bitmap* в структуре TSS процессора исключительно для тех портов, которые драйвер указал в массиве `allowed_ports`. Доступ к остальным портам вызовет исключение. Указание 0xFFFF в качестве порта разрешает доступ ко всем портам.
* **`DRV_PERM_PHYS_MAP`** — Право вызывать маппинг произвольной физической памяти в свое виртуальное адресное пространство. Критически важно для драйверов видеокарт и устройств, использующих MMIO.
* **`DRV_PERM_EDIT_SYSTEM_FLAGS`** — Право изменять глобальные флаги ядра (например, отключать отладочный вывод ядра на экран при переходе в графический режим).
* **`DRV_PERM_GET_SPEC_INFO`** — Право запрашивать у ядра специфичную загрузочную информацию, переданную от BIOS/UEFI.

## 2. Демоны

Демоны — это процессы, которые предоставляют сервисы другим программам, но **не требуют прямого доступа к оборудованию**. К ним относятся, например, виртуальные файловые системы (IPC-FS), сетевые стеки, менеджеры окон или системные службы.

### Механизм регистрации
В отличие от аппаратных драйверов, демоны не используют секцию `.driver_info`. Любой процесс может объявить себя демоном прямо во время выполнения, используя системный вызов регистрации драйвера. 

Регистрация нужна исключительно для **маршрутизации IPC**. Она привязывает текущий PID процесса к определенному типу (`driver_type_t`) или строковому имени. Это позволяет другим процессам находить демона в системе, не зная заранее его PID.

*Примечание: Системный вызов регистрации отклонит запрос, если процесс попытается запросить аппаратные привилегии (например, доступ к портам) — такие права выдаются только при парсинге ELF-файла ядром.*

## Жизненный цикл и Инициализация

Процесс запуска драйверов строго регламентирован для предотвращения состояния гонки (race conditions), когда приложение пытается обратиться к драйверу, который еще не успел инициализироваться.

### 1. Загрузка из InitRD
Самые критичные драйверы загружаются самим ядром из архива `INITRD.TAR` (см. [Структура файлов ОС](../files.md#содержимое-и-структура-initrd-tar)).
* **AuthDriver** — Демон прав доступа.
* **VFSDriver** — Демон виртуальной файловой системы.
* **InitDriver** — Процесс инициализации, который берет на себя дальнейшую загрузку ОС.

### 2. Загрузка по конфигурации
`InitDriver` читает файл [`/configs/drivers.conf`](../configs.md#driversconf) и начинает последовательный запуск остальных драйверов (PCI, Video, Input, Window Manager).

### 3. Статусы готовности (Driver Status)
При создании драйвер получает статус `DRV_STAT_CREATED`. 
`InitDriver`, запустив драйвер, приостанавливает свою работу и ждет. Драйвер обязан выполнить свою внутреннюю инициализацию (настроить оборудование, выделить память) и затем явно сообщить ядру о своей готовности, сменив свой статус на `DRV_STAT_READY`. Только после этого `InitDriver` продолжит загрузку следующего драйвера или пользовательских приложений.

## Взаимодействие

Поскольку драйверы изолированы в своих адресных пространствах, взаимодействие с ними происходит следующим образом:

1. **Поиск (Discovery):** Клиентское приложение запрашивает у ядра PID нужного драйвера, передавая его тип (например, `DT_VIDEO`) или строковое имя (если это кастомный демон).
2. **Общение (IPC):** Получив PID, клиент общается с драйвером через стандартный механизм [сообщений и разделяемой памяти (Shared Memory)](../kernel/README.MD#межпроцессное-взаимодействие-ipc).
3. **Приоритеты:** Чтобы система оставалась отзывчивой, большинство драйверов и демонов самостоятельно повышают свой приоритет планировщика до `THREAD_PRIO_REALTIME`.
