# Структура файлов ОС

Актуально для версии коммита 108.

В данном документе описано физическое и логическое расположение файлов операционной системы AOS на загрузочном носителе, структура виртуального диска первоначальной загрузки, а также бинарный формат заголовка ядра.

## Структура загрузочного раздела

Поскольку система по умолчанию использует файловую систему FAT32, корень диска должен содержать строго определенный набор файлов для успешной работы оригинальных или кастомных загрузчиков.

### Корневая директория
* `/AOSLDR.BIN` - Основной бинарный файл ядра операционной системы AOS (совмещает в себе функции загрузчика третьего этапа и микроядра для BIOS Legacy)
* `/INITRD.TAR` - Несжатый архив начального диска в оперативной памяти. Содержит обязательные драйверы для запуска ОС.
* `/PBRLDR.BIN` - Загрузчик второго этапа, необходимый для BIOS Legacy
* `/configs/` - Конфигурация системы. Подробнее здесь -> [Конфигурация системы](configs.md) <-
* `/assets/` - Различные неисполняемые файлы (шрифты, фон, иконки и т.д.)
* `/bin/` - Пользовательские программы и утилиты системы. Подробнее здесь -> [Пользовательские программы](bin_folder.md) <-
* `/linux/` - *(В разработке)* Портированные программы Линукса
* `/EFI/BOOT/BOOTX64.EFI` — *(В разработке)* Загрузчик для систем с поддержкой UEFI

## Содержимое и структура INITRD.TAR

Архив `INITRD.TAR` считывается загрузчиком в память и используется ядром для загрузки обязательных . Внутри него строго обязательны следующие исполняемые файлы (формата ELF64) и директории:

```text
INITRD.TAR/
|-- AUTHDRIVER.ELF    # Драйвер контекста безопасности и прав доступа
|-- VFSDRIVER.ELF     # Драйвер виртуальной файловой системы
|-- INITDRIVER.ELF    # Драйвер-инициализатор пользовательского пространства
```

*Примечание: Расширения файлов и ВЕРХНИЙ РЕГИСТР для драйверов внутри initrd ОБЯЗАТЕЛЬНЫ.*

## Загрузка и загрузчики

Написание своих кастомных загрузчиков для AOS приветствуется. На данный момент поддерживаются следующие варианты загрузки системы:

### BIOS Legacy

На данный момент является основным загрузчиком. Загрузка происходит через PBR, записанный на раздел с форматом FAT32 (см. [здесь](#почему-система-находится-на-fat32)). Ядро имеет спциализированную точку входа для систем с BIOS (несовместима с другими загрузчиками). Физический адрес - AOSLDR.BIN+0x0, виртуальный - 0x10000. При написании кастомных загрузчиков для BIOS убедитесь, что ваши адреса совместимы с аресами AOS, иначе система будет работать непредсказуемо.

### UEFI

*В разработке (планируется в ближайших коммитах).* Будет использовать стандартный путь `/EFI/BOOT/BOOTX64.EFI` на EFI-системном разделе.

## Почему система находится на FAT32?

На самом деле, AOS запустится и на любой другой файловой системе, если архитектура поддерживает и имеется необходимая файловая система. Но по умолчанию всегда будет FAT32, так как ее поддерживают BIOS и UEFI. Возможно в будущем это изменится, но на ближайшее будущее изменения не планируются

# Структура заголовка файла ядра

Некоторые данные могут отличаться
```hexdump
EB 1E 41 4F 53 4C 44 52 51 11 01 00 00 00 00 00 |ë.AOSLDRQ.......|
03 00 00 00 00 70 00 00 00 00 00 00 90 90 90 90 |.....p..........|
```
| Смещение | Размер (байты) | Сигнатура / Значение | Описание |
| :--- | :--- | :--- | :--- |
| `0x00` | 2 | `EB 1E` | Инструкция `jmp short 0x20`. Используется BIOS-загрузчиком для безопасного прыжка через технические данные заголовка сразу на исполняемый код. |
| `0x02` | 6 | `41 4F 53 4C 44 52` | Магическая строка `"AOSLDR"` в кодировке ASCII. Служит для валидации подлинности файла ядра сторонними загрузчиками. |
| `0x08` | 8 | *Указатель (например, `0x11151`)* | Указатель на основную мультитехнологическую точку входа `kernel_main`. **Все загрузчики (кроме Legacy BIOS)** обязаны считывать этот 8-байтовый адрес и передавать управление туда. |
| `0x10` | 4 | *Целое число (например, `3`)* | Версия интерфейса ядра. Сторонний загрузчик обязан сверять это поле на совместимость перед прыжком. |
| `0x14` | 8 | *Указатель (например, `0x7000`)* | Гарантированный физический адрес памяти, куда загрузчик может безопасно записать структуру `boot_info_t` для передачи параметров ядру. |
| `0x1C` | 4 | `90 90 90 90` | Четыре инструкции `nop`. Выравнивающий патч и безопасная заглушка, завершающая структуру технического заголовка. |
