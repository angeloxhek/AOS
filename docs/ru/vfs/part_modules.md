# Стандарт написания парсеров разделов

Актуально для версии коммита 108.

Парсеры разделов (Partition Modules) — это компоненты VFS, отвечающие за анализ структуры диска. Их задача — прочитать служебные сектора (например, MBR, GPT, APM), найти логические тома (разделы) и сообщить об их границах ядру VFS.

Парсеры компилируются **внутри процесса VFS** (`VFSDRIVER.ELF`) и работают исключительно через абстракцию блочного устройства (`block_dev_t`). Они не взаимодействуют с оборудованием напрямую.

## 1. Интерфейс

Каждый парсер должен реализовать структуру `part_driver_t`, описанную в `data/include/vfs/part_interface.h`:

```c
typedef void (*part_found_cb_t)(block_dev_t* raw_disk, uint8_t part_id, uint64_t start_lba, uint64_t size_sectors, int is_bootable, void* context);

typedef struct {
    const char* name; // Имя парсера (например, "mbr", "gpt")
    
    // Функция анализа диска. Возвращает 1, если таблица разделов найдена, иначе 0.
    int (*parse)(block_dev_t* raw_disk, const part_boot_desc_t* boot_desc, part_found_cb_t callback, void* context);
} part_driver_t;
```

### Важное архитектурное правило: Неразрушающее чтение
Функция `parse` не должна изменять состояние диска. Она должна только читать сектора с помощью `block_read`. Если прочитанные данные не соответствуют ожидаемым магическим сигнатурам (например, нет `0x55AA` в конце сектора для MBR), парсер должен немедленно вернуть `0`, чтобы VFS мог передать диск следующему парсеру.

## 2. Пошаговая реализация модуля

### Шаг 1: Чтение и проверка сигнатур
Парсер должен прочитать сектор(ы), где ожидается таблица разделов, и проверить магические числа.

```c
#include <stdlib.h>
#include <vfs/disk_interface.h>
#include <vfs/part_interface.h>

static int my_parse(block_dev_t* raw_disk, const part_boot_desc_t* boot_desc, part_found_cb_t callback, void* context) {
    uint8_t* sector = malloc(raw_disk->sector_size);
    if (!sector) return 0;

    // Читаем первый сектор диска (LBA 0)
    if (block_read(raw_disk, 0, 1, sector) != 0) {
        free(sector);
        return 0;
    }

    // Проверяем магическую сигнатуру нашей таблицы разделов
    if (sector[510] != 0x55 || sector[511] != 0xAA) {
        free(sector);
        return 0; // Это не наша таблица разделов
    }
    
    // ... продолжение парсинга ...
```

### Шаг 2: Определение загрузочного раздела
VFS передает в парсер структуру `boot_desc`, которая содержит информацию от загрузчика ОС о том, с какого физического диска и раздела была загружена система.

Парсер должен сравнить данные из таблицы разделов с `boot_desc`, чтобы определить, является ли текущий раздел загрузочным.

```c
    uint32_t disk_signature = *(uint32_t*)&sector[440]; // Пример для MBR
    
    // ... цикл по записям таблицы разделов ...
    uint64_t part_start_lba = ...;
    uint64_t part_size_sectors = ...;
    
    int is_bootable = 0;
    if (boot_desc && boot_desc->type == PART_BOOT_MBR) {
        if (boot_desc->specific.mbr.drive_sign == disk_signature &&
            boot_desc->specific.mbr.part_lba == part_start_lba) {
            is_bootable = 1;
        }
    }
```

### Шаг 3: Вызов Callback-функции
Для каждого найденного валидного раздела парсер обязан вызвать функцию `callback`. Это сообщит VFS о необходимости создать виртуальное блочное устройство для этого раздела.

```c
    // Если раздел не пустой
    if (part_size_sectors > 0) {
        // Вызываем callback, передавая:
        // 1. Исходный диск
        // 2. Локальный ID раздела (0, 1, 2...)
        // 3. Смещение раздела в секторах от начала диска
        // 4. Размер раздела в секторах
        // 5. Флаг загрузочного раздела (1 или 0)
        // 6. Контекст VFS (передается "как есть")
        callback(raw_disk, part_id, part_start_lba, part_size_sectors, is_bootable, context);
    }
```

### Шаг 4: Возврат результата
Если парсер успешно распознал таблицу разделов (даже если в ней нет ни одного раздела), он должен вернуть `1`. Это скажет VFS прекратить попытки применить другие парсеры к этому диску.

```c
    free(sector);
    return 1; // Таблица успешно распознана
}
```

## 3. Регистрация модуля в VFS

Чтобы VFS узнал о новом парсере, его необходимо добавить в глобальный массив `available_parsers` в файле `data/initdrivers/vfs/vfsdriver.c`.

1. Экспортируйте структуру драйвера в конце вашего файла:
```c
part_driver_t my_part_driver = { 
    .name = "mypart", 
    .parse = my_parse 
};
```

2. Добавьте драйвер в `vfsdriver.c`:
```c
extern part_driver_t gpt_part_driver;
extern part_driver_t mbr_part_driver;
extern part_driver_t my_part_driver; // <-- Объявление

part_driver_t* available_parsers[] = {
    &gpt_part_driver,
    &mbr_part_driver,
    &my_part_driver, // <-- Регистрация
    0 // Нуль-терминатор обязателен!
};
```

*Примечание: Порядок парсеров в массиве имеет значение. VFS применяет их по очереди. Более строгие форматы (например, GPT) должны идти раньше менее строгих (MBR), так как GPT содержит защитный MBR, который может ложно сработать.*

## 4. Правила и ограничения

1. **Динамическая память:** Всегда освобождайте выделенную память (`free`) перед выходом из функции `parse`, независимо от того, успешен парсинг или нет. Утечки памяти в VFS недопустимы.
2. **Размер сектора:** Не предполагайте, что размер сектора всегда равен 512 байт. Используйте `raw_disk->sector_size` для выделения буферов и расчетов (например, CD-ROM использует сектора по 2048 байт).
3. **Вложенные разделы (Extended Partitions):** Если формат поддерживает вложенные разделы (как Extended Boot Record в MBR), парсер должен рекурсивно или итеративно обойти их и вызвать `callback` для каждого логического диска. Смещение (`start_lba`) всегда должно быть абсолютным от начала физического диска.
