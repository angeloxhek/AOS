# Архитектура микроядра AOS

Актуально для версии коммита 108.

AOS построена на базе микроядерной архитектуры. Ядро выполняет только минимально необходимый набор функций: управление памятью, планирование потоков и обеспечение межпроцессного взаимодействия (IPC). Вся остальная логика (ФС, сеть, драйверы устройств) вынесена в пользовательское пространство (Ring 3).

## Управление памятью (PMM и VMM)
* **PMM (Physical Memory Manager):** Работает на основе битовой карты (Bitmap). Оперирует блоками по 4 КБ.
* **VMM (Virtual Memory Manager):** Каждому процессу выделяется собственное адресное пространство (PML4). Ядро использует механизм временного маппинга (`temp_map`) для безопасного доступа к физическим страницам других процессов.
* **Shared Memory (SHM):** Основной механизм передачи больших объемов данных. Ядро выделяет анонимные физические страницы и мапит их в виртуальное пространство запросившего процесса. Доступ другим процессам выдается явно через систему разрешений SHM.

## Планировщик (Scheduler)
Планировщик является вытесняющим (Preemptive) и работает по алгоритму Round-Robin с учетом приоритетов.
Поддерживается 3 уровня приоритета (`THREAD_PRIO_LEVELS`):
1. `THREAD_PRIO_REALTIME` (Высший - для драйверов)
2. `THREAD_PRIO_SYSTEM`
3. `THREAD_PRIO_NORMAL` (По умолчанию для пользовательских приложений)

## Межпроцессное взаимодействие (IPC)
IPC в AOS реализовано через обмен фиксированными сообщениями (`message_t` - 112 байт) и разделяемую память.
* Сообщения ставятся в очередь целевого процесса.
* Ядро гарантирует подлинность поля `sender_pid` (PID отправителя).
* Процесс может ожидать сообщения синхронно (блокируя поток) или проверять очередь асинхронно.
* Для предотвращения DoS-атак существует лимит очереди сообщений (`ipc_queue_limit`), который может быть изменен.
