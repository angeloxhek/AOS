# Спецификация системы сборки

Актуально для версии коммита 108.

В данном документе описана структура и логика работы главного сборочного файла `/Makefile` операционной системы AOS. Система сборки поддерживает кросс-компиляцию, модульное включение драйверов и сборку слоев совместимости.

## Переменные окружения и конфигурация

При запуске `make` можно передавать следующие параметры для управления процессом сборки:

| Переменная | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `ARCH` | `x86_64` | Целевая архитектура процессора. Автоматически подключает файл `data/arch/$(ARCH)/arch.mk`. |
| `CROSS_COMPILE` | *Пусто* | Префикс инструментария кросс-компиляции (например, `x86_64-elf-`). |
| `DEBUG` | *Не задано* | Если равен `1`, включает режим отладки: активирует `-DDEBUG_MODE`, добавляет `-g3 -O0` и внедряет таблицу символов ядра через `gensyms.py`. В противном случае сборка оптимизируется по размеру (`-Oz`). |
| `V` | *Не задано* | Если равен `1`, отключает скрытие команд (`@`) в консоли, выводя полные строки вызова компилятора и линкера. |

## Структура директорий сборки

Все временные и финальные файлы распределяются по следующим каталогам:
* `/build/$(ARCH)/` — Корневая папка готовой сборки для выбранной архитектуры.
* `/build/$(ARCH)/volume/` (`DISK_DIR`) — Будущий корень загрузочного диска FAT32. Сюда собираются `AOSLDR.BIN`, файлы конфигурации и пользовательские бинарники.
* `/temp/` — Директория для хранения промежуточных объектных файлов (`.o`) и карт компиляции (`.map`).
* `/debug/` — Экспортируемые несплитнутые ELF-бинарники с отладочной информацией (копируются сюда только при `DEBUG=1`).

## Основные цели сборки

### `all`
**Дефолтная цель.** Выполняет полную сборку операционной системы. Последовательно вызывает:
1. `prepare` — Создает необходимую структуру папок в `/build` и `/temp`.
2. `kernel` — Компилирует базовые модули ядра и упаковывает `AOSLDR.BIN` и `INITRD.TAR`.
3. `libs` — Собирает системные библиотеки `libaos.a` и слой совместимости Linux `libaoslin.a`.
4. `drivers` — Подключает внешние драйверы через подмодули.
5. `configs` — Копирует папки со статическими ресурсами `/assets` и настройками `/configs` на целевой диск.
6. `userspace` — Собирает графическую оболочку (`desktop.elf`) и системный менеджер (`aex.elf`).
7. `userlinux` — Компилирует утилиты из папки `userlinux` (например, `tree`) с использованием Linux-совместимой libc.

### `kernel`
Отвечает за сборку ядра. Процесс линковки ядра (`AOSLDR.BIN`) при `DEBUG=1` проходит в **два этапа**:
* **Проход 1:** Производится предварительная линковка объектных файлов ядра в промежуточный `aosldr_tmp.elf`.
* **Генерация символов:** Скрипт `scripts/gensyms.py` парсит полученный ELF-файл, извлекает адреса функций и генерирует исходный код таблицы символов `ksyms.c`.
* **Проход 2:** Компилируется `ksyms.c` и ядро перелинковывается заново с вшитой таблицей символов в финальный `aosldr.elf`.
* **OBJCOPY:** Из ELF-файла вырезаются секции `.bss`, `.note`, `.comment` и формируется чистый бинарный образ ядра.

### `clean`
Полностью очищает окружение: удаляет содержимое папок `/temp`, `/build`, `/debug`, а также рекурсивно вызывает `clean` внутри подкаталогов SDK (`sdk/aoslib` и `sdk/aosliblin`).

## Модульное включение (Подкаталоги)

Makefile использует механизм `include` для динамического расширения рецептов сборки без засорения главного файла:
* `data/arch/$(ARCH)/arch.mk` — Специфичные флаги компилятора (`ARCH_CFLAGS`), линкера (`ARCH_LDFLAGS`) и дополнительные файлы объектов для выбранной платформы.
* `data/initdrivers/make.mk` — Сборочный файл критически важных драйверов, помещаемых внутрь первоначального RAM-диска (`INITRD.TAR`).
* `data/drivers/make.mk` — Правила для сборки дополнительных динамических драйверов, устанавливаемых в `/drivers/` на диске.
